# 按设计图建模（Reference Matching）

用于"照着多角度设计图/效果图建出一致模型"的任务。

**核心认知：代理看不准自己的渲染结果。** 所有"完全一致"的努力最后都卡在这里——它没法把自己做的东西和设计图做可靠比对。

所以方法分两半：**把设计图转成数值约束**，然后**建立一个客观比对的闭环**。

与 `gates.md` 的分工：那份讲各领域现成的门槛，这份讲**怎么从一张设计图里造出门槛**。

---

## 阶段 0 — 参考图审计（跳过这步后面全白做）

**本阶段不建任何模型。**

### 0.1 判断每张视图是正交还是透视

**最容易被忽略的致命问题。** AI 生成的"三视图"绝大多数是透视渲染贴上了"正视图"的标签。**透视图不能用来量尺寸。**

判定方法：找物体上本该平行的两条边（柜子的上下沿、桌面的前后沿），在图上量夹角。**收敛即为透视**，量出来的比例全是错的。

结论写进方案：正交图可对齐建模，透视图**只能看形态**。

### 0.2 建立比例基准

找**一个**可信尺寸作为锚点，其余全部由比例推导。

优先级：
1. 标注尺寸表（通常可信）
2. 已知标准物：门高 2000mm、床垫 1500×2000、插座离地 300mm、踏步高 150mm
3. 人物身高（仅当图中有人且姿态可判断）

**锚点只要一个。** 多个锚点会互相矛盾，届时不知道该信哪个。

### 0.3 像素测量

**别让代理"看"图估比例，让它算。** 图片就在磁盘上：

```python
from PIL import Image
import numpy as np

img = np.array(Image.open(path).convert('L'))
mask = img < 200                      # 阈值按图调
rows, cols = np.where(mask)
print("bbox px:", cols.min(), cols.max(), rows.min(), rows.max())
```

进一步可做边缘检测找主要直线位置，得到内部分割比例（例："抽屉分层线位于总高 38% 处"）。

**这类数值比目视估计可靠一个量级**，且换个模型执行结果一样。所有后续门槛都建立在这些测量值上。

### 0.4 标记不自洽处并当场裁决

AI 生成的多视图几乎一定有矛盾。**开工前列出来，逐条判定听谁的，写进方案。**

默认权重（可按项目调整，但必须显式声明）：

1. 透视图 / 主视角 — 定整体轮廓、比例、氛围
2. 尺寸标注 — 通常可信，直接采用
3. 正视图 — 定比例关系
4. 侧视图 / 次要视图 — 仅作参考，**不严格对齐**

留到建模中途再纠结会陷入死循环。

### 0.5 标出无参考区域

参考图不显示背面和内部，那些地方只能设计而非复刻。

**在方案里明确列出哪些区域没有参考**，让代理按合理性处理，而不是假装有依据。这一条能防止它把编出来的部分当成有据可查，进而在后续验收时误判。

**阶段 0 验收：** 提交审计报告——每张图的正交/透视判定（附平行线测试数值）、比例锚点、像素测量得到的关键比例表、不自洽处清单及裁决、无参考区域清单。

## 阶段 1 — 对齐脚手架

### 1.1 正交参考笼

把审计通过的正交视图作为 Empty (Image) 摆成前/侧/顶三面，按真实尺寸缩放定位：

```python
e = bpy.data.objects.new("REF_Front", None)
e.empty_display_type = 'IMAGE'
e.data = bpy.data.images.load(front_path)
e.empty_display_size = 0.5          # 按比例锚点换算
e.empty_image_offset = (-0.5, -0.5) # 居中
```

摆好之后建模就是描图。**摆放精度直接决定整个任务的上限**，这一步要单独验收。

### 1.2 关键点标注（把"像不像"变成数字）

从参考图提取特征点的真实坐标，在场景里放 Empty 作为硬目标：

- 分割线高度
- 台沿外沿位置
- 支撑腿落地点
- 洞口/开孔中心

验收项随之变成：**"顶点 X 到 Empty Y 的距离 < 3mm"**。可计算，非审美判断。

这是把主观转客观最直接的手法。

**阶段 1 验收：** 参考笼三面的尺寸与比例锚点一致；关键点 Empty 数量与阶段 0 清单一致。

---

## 阶段 2 — 参数化骨架

**这一条决定闭环能转多少圈。**

把所有尺寸提到脚本顶部的参数字典，整个模型从参数生成，**且脚本可重复执行**（先删后建）：

```python
P = {
  "width": 0.50, "depth": 0.50, "height": 0.15,
  "bevel": 0.0025, "drawer_split": 0.38,
}
```

修正循环变成：**调一个数 → 重跑 → 重新测量**。

对照直接建模：改一次形状可能毁掉下游所有细节，闭环转两三圈就转不动了。**参数化做得好能转十几圈——这是要不要参数化的真正判据。**

（节点图式的工具天生就是这个结构，这也是它在此类任务上有优势的根本原因。）

**阶段 2 验收：** 包围盒达标；主体分割比例与阶段 0.3 的测量值一致（误差 < 2%）。

---

## 阶段 3 — 剪影闭环（核心技术）

这是"一致性"唯一可靠的度量方式。

### 3.1 原理

用正交相机渲纯白剪影，与参考图的二值化剪影算 **IoU（交并比）**。IoU 是一个数——代理能读、能追踪、能据此判断改动是变好还是变坏。

### 3.2 实现

```python
import numpy as np
from PIL import Image

def silhouette_iou(render_path, ref_path, size=1024):
    a = np.array(Image.open(render_path).convert('L').resize((size,size))) > 127
    b = np.array(Image.open(ref_path).convert('L').resize((size,size))) > 127
    inter = (a & b).sum()
    union = (a | b).sum()
    ca = np.array(np.where(a)).mean(axis=1)
    cb = np.array(np.where(b)).mean(axis=1)
    return inter / union, (ca - cb)     # IoU, 质心偏移(px)
```

### 3.3 渲染侧要求

- **正交相机**，视角严格匹配参考视图
- Emission 纯白材质 + 黑背景（或 Workbench flat 模式）
- 关闭所有灯光与后处理
- 分辨率与参考图一致

### 3.4 门槛

| 类型 | IoU 目标 |
|---|---|
| 硬表面（家具、机械、建筑构件） | **≥ 0.95** |
| 半有机（布料、软包、抱枕） | ≥ 0.88 |
| 有机（植物、毛发） | **不适用**，改用阶段 4 的特征清单 |

**质心偏移必须与 IoU 一起报告：**

- IoU 低、质心对齐 → 形状真的不对，改模型
- IoU 低、质心偏移 → 可能只是摆位问题，**先改摆位再判断**

不看质心就改模型，是这一步最常见的浪费。

### 3.5 相机匹配是前提

**相机不匹配，IoU 完全没有意义。**

正交视图容易匹配。45° 透视图需要相机解算，难度高一个量级。

**建议：不要把透视图作为主要门槛。** 用正交三视图跑 IoU 闭环，透视图只用于核对不可数值化的特征。

**阶段 3 验收：** 逐视图报告 IoU 与质心偏移的具体数值（不是"已达标"这类结论），全部达门槛。

---

## 阶段 4 — 特征清单

IoU 抓不到内部特征。用**可数项**补齐——数量是数字，代理能可靠核对。

模板：

| 特征 | 目标值 |
|---|---|
| 零件数量（扇叶/抽屉/层板/主干） | |
| 分割数量（窗框竖框、面板分缝） | |
| 比例关系（总高 / 底座高） | |
| 位置比例（最宽处位于 X% 高度） | |
| 可穿透性（能否看穿见背景） | |

这类清单能挡住"轮廓对了但零件数不对"这种很显眼的偏差。

**有机形态专用。** 植物、毛发、布料褶皱做不到剪影级匹配，也不该要求。对它们，特征清单是**唯一**可靠的门槛。例：

- 树高为盆高的 5～5.5 倍
- 主干 6～8 根，根部并拢向上微张
- 最宽处位于约 60% 高度
- 能看穿枝叶见背景

**阶段 4 验收：** 清单逐项核对通过，且 IoU 未因加细节而退化。

---

## 建模顺序：按约束强度递减

```
1. 整体包围盒        ← 尺寸表，约束最强
2. 主体块分割比例     ← 正交图像素测量
3. 轮廓曲线          ← 剪影 IoU 闭环
4. 内部特征          ← 特征清单
5. 细节与倒角        ← 透视图 / 特写图
```

**绝对不要从细节开始。** 先做细节再调整体，细节全部要重做。

---

## 明确禁止

1. 用透视图测量尺寸。
2. 设置多个比例锚点。
3. 目视估计比例（图在磁盘上，用脚本量）。
4. 在相机未匹配的情况下使用 IoU 数值。
5. 只看 IoU 不看质心偏移就去改模型。
6. 把 45° 透视图作为主要 IoU 门槛。
7. 从细节开始建模。
8. 把无参考区域的推测当作有据可依。
9. 报告"已达标"而不报具体数值。

---

## 诚实的边界

**1. "完全一致"达不到，追它是个陷阱。** AI 生成的设计图内部不自洽；硬要三视图全部严格对齐，会得到一个哪个视图都不像的东西。**IoU 0.95 已经是肉眼分辨不出的水平**，到此为止。

**2. 遮挡区域是设计决策。** 见 0.5。

**3. 有机形态上限低得多。** 不要对植物、毛发、褶皱要求剪影级匹配。

**4. 闭环圈数有上限。** 参数化做得好能转十几圈，直接建模三圈就死。这是要不要参数化的真正判据。

---

## 症状 → 原因

| 症状 | 应检查 |
|---|---|
| 比例怎么调都对不上 | 拿透视图当图纸了，重做 0.1 |
| 不同视图的尺寸互相矛盾 | 设了多个比例锚点，退回 0.2 |
| IoU 很低但看着挺像 | 相机未匹配；或质心偏移大，先改摆位 |
| IoU 上不去且质心已对齐 | 轮廓确实不对，回阶段 2 改参数 |
| 加细节后 IoU 反而下降 | 细节尺寸超出设计值，或倒角过大 |
| 改一处形状毁掉一片细节 | 未参数化，闭环已死，重建骨架 |
| 轮廓很准但一眼看出不对 | 内部特征数量不对，查阶段 4 清单 |
| 有机物体 IoU 永远不达标 | 有机形态不适用 IoU，改用特征清单 |
| 背面结构存疑 | 属无参考区域，查 0.5 清单确认是设计而非错误 |
